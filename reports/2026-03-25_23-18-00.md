# Kain Architecture Review: Momentum & Viability (2026-03-25)

## What Kain Currently Is
Kain is a compiled, multi-target language toolchain and embeddable runtime host stack. It has evolved from a simple compiler into a layered system capable of compiling `.kn` to multiple targets (web, native, GPU, UE5), importing foreign source, running in host-backed execution lanes (C, Rust, Python, Node), and materializing native/UI/3D applications. It acts as both a language and an orchestrator of execution contexts.

## What is Currently Possible & Capabilities
- **Language/Compiler:** Active frontend parsing, typechecking, comptime execution, and runtime-contract emission via `kain-core`.
- **Orchestration:** Emitting bundles, artifacts, and multi-runtime workflows via `kain-driver`.
- **Bridges:** Seamlessly embedding and running with Python, Node, C ABI, and Rust crates via `kain-interop`.
- **UI/3D/Native:** Semantic UI graph compilation, accelerated native presentation (`kain-ui-native`), and a 3D renderer/viewport stack (`kain-3D`).
- **GPU Pipelines:** Emitting shader bundle metadata and running Vulkan compute executors consuming emitted shader bundles and residency metadata.

## Self-Hosting & Universal-Language Goals
Kain is moving closer to universal orchestration. The `kain-selfhost` and `kain-omni` crates indicate a strong push toward mixed-language orchestration and self-reliance. However, the true universal promise relies heavily on the embeddable runtime contracts and bridge lanes working seamlessly rather than just cross-compiling text.

## GPU-Based Pipeline Design & Critique
- **Current Design:** Compute truth begins in `kain-core` as comptime metadata, which emits workgroup/dispatch/tensor metadata into realtime bundles. `kain-gpu-runtime` (Vulkan dispatch) consumes these.
- **Critique:** The recent Alpha phase 2 update synthesized render-graph, residency, and compute-schedule surfaces from emitted graphics-bundle truth. This is a massive step forward from host-local heuristics, but the current implementation still relies on synthesized heuristics rather than compiler-authored explicit execution tables.
- **Risk:** If the runtime/native lane diverges from the compiler's emitted truth, the entire execution model fragments.

## Bottlenecks, Missing Primitives, Ergonomics Issues, Performance Risks
- **Missing Primitives:** Runtime-owned scene registry behind opaque scene handles; fully wired live-host query engine for runtime inspection; explicit compiler-authored render/residency/schedule tables (currently synthesized).
- **Ergonomics Issues:** Ingestion descriptors exist, but bundle loading still largely relies on legacy path/environment-variable conventions, making the developer experience brittle.
- **Bottlenecks/Risks:** The native UI and Win32 viewport lanes are not yet consuming the newly landed Alpha contracts (scene handles, query requests) end-to-end. Performance risks lie in the synthesized nature of the render graph and residency bytes—these need to become explicit compiler truth to guarantee safe cross-lane ordering.

## Relative Positioning (C++, Rust, TypeScript)
- **vs. C++:** Safer and more orchestrated. Kain abstracts the ABIs and execution pipelines, making cross-boundary interop (GPU/native) a first-class language feature rather than a library afterthought.
- **vs. Rust:** Rust is currently Kain's host substrate. Kain trades Rust's strict local borrow checker for higher-level semantic orchestration of execution contexts (UI, 3D, GPU, mixed runtimes) via bundles, aiming for a smoother "raw thought to multi-target app" flow.
- **vs. TypeScript:** Much lower-level control. Where TS orchestrates JS objects, Kain orchestrates native ABI payloads, shaders, and host memory, bridging the gap between scripting ergonomics and systems-level performance.

## What Should Happen Next (Translating Raw Thought to Code)
To close the gap between raw intent and executing code, momentum must focus on:
1. **Wire the Alpha Contracts:** Force the Win32 viewport and native UI shell to consume the new scene/query contracts end-to-end. Stop smuggling editor semantics into platform-specific message handlers.
2. **Build the Scene Registry:** Implement the first runtime-owned scene registry behind the new opaque scene handles.
3. **Compiler-Authored Execution Tables:** Upgrade the synthesized render-graph and residency heuristics into explicit, compiler-authored truth by widening the emitters in `kain-core`.
4. **Unify Ingestion:** Transition all bundle and asset loading to use the new ingestion descriptors rather than fragile environment variables.
5. **Delta Editor Integration:** Ensure the Delta workspace/editor shell consumes these canonical Alpha contracts to provide a stable, introspectable development environment.
