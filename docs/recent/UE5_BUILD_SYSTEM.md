# KAIN UE5 Build System Guide

## Overview

KAIN provides an automated build system for UE5 plugins that eliminates manual file copying and ensures correct shader paths. Write your shaders once in KAIN, run one command, and get a complete UE5 plugin with all files in the correct locations.

## Quick Start

### 1. Create Your Plugin Structure

```
MyPlugin/
├── KAIN.toml          # Build configuration
├── MyShaders.kn       # Your KAIN shader source
└── (generated files will go here)
```

### 2. Create KAIN.toml

```toml
[package]
name = "MyPlugin"
version = "1.0.0"
description = "My awesome UE5 plugin"

[build]
entry = "MyShaders.kn"
output = "dist"

[ue5]
plugin_name = "MyPlugin"
plugin_dir = "."
shaders = [
    "MyFirstShader",
    "MySecondShader"
]
```

### 3. Write Your Shaders

Create `MyShaders.kn`:

```kain
shader fragment MyFirstShader(uv: Vec2) -> Vec4:
    uniform intensity: Float @0
    uniform color: Vec3 @1
    
    return vec4(color * intensity, 1.0)

shader fragment MySecondShader(uv: Vec2) -> Vec4:
    uniform tint: Vec3 @0
    
    let pattern = sin(uv.x * 10.0) * cos(uv.y * 10.0)
    return vec4(tint * pattern, 1.0)
```

### 4. Build the Plugin

```bash
kain build --ue5
```

### 5. Generated Structure

```
MyPlugin/
├── KAIN.toml
├── MyShaders.kn
└── MyPlugin/                    # Generated plugin
    ├── Source/
    │   ├── Public/
    │   │   ├── MyFirstShader.h
    │   │   └── MySecondShader.h
    │   └── Private/
    │       ├── MyFirstShader.cpp
    │       └── MySecondShader.cpp
    └── Shaders/
        ├── MyFirstShader.usf
        └── MySecondShader.usf
```

## KAIN.toml Configuration

### [package] Section

```toml
[package]
name = "MyPlugin"           # Plugin name
version = "1.0.0"           # Semantic version
description = "Optional"    # Plugin description
authors = ["Your Name"]     # Optional authors list
```

### [build] Section

```toml
[build]
entry = "MyShaders.kn"      # Main KAIN source file
output = "dist"             # Output directory for non-UE5 builds
targets = ["wasm", "js"]    # Optional: multi-target builds
```

### [ue5] Section

```toml
[ue5]
plugin_name = "MyPlugin"    # REQUIRED: Plugin name (used in shader paths)
plugin_dir = "."            # Plugin output directory (relative to KAIN.toml)
shaders = [                 # List of shader names to compile (if manual implementation is used, however it has an auto discover feature)
    
]
```

**Note:** If `shaders` array is empty, KAIN will auto-detect all shaders in the source file.

## CLI Commands

### Build UE5 Plugin

```bash
kain build --ue5
```

Reads `KAIN.toml` in current directory and generates complete UE5 plugin structure.

### Build with Custom Plugin Name

```bash
kain MyShaders.kn -t usf -o OutputName --plugin MyPluginName
```

Single-file compilation with explicit plugin name (legacy mode).

### Multi-Target Build

```bash
kain build
```

Builds all targets specified in `KAIN.toml [build.targets]`.

### Watch Mode

```bash
kain MyShaders.kn -t usf -o Output --plugin MyPlugin -w
```

Automatically recompiles on file changes.

## UE5 Codegen Pipeline

### Phase 1: Parsing

```
.kn source → Lexer → Tokens → Parser → AST
```

KAIN parses your shader code into an Abstract Syntax Tree (AST) containing:
- Shader definitions (name, stage, inputs, outputs)
- Uniform declarations with bindings
- Shader body (expressions, statements)

### Phase 2: Type Checking

```
AST → Type Checker → Typed AST
```

Validates:
- Type correctness (Vec3 + Float = error)
- Uniform binding uniqueness
- Shader stage compatibility
- Return type matching

### Phase 3: USF Generation

```
Typed AST → USF Codegen → .usf file
```

Generates UE5-compatible HLSL:
- `#include "/Engine/Public/Platform.ush"` headers
- Global uniform declarations
- Texture/sampler bindings with `register(t0)`, `register(s0)`
- UAV bindings with `register(u0)` for compute shaders
- Entry point functions: `ShaderNamePS()` or `ShaderNameCS()`
- `[numthreads(8,8,1)]` for compute shaders

**Example Output:**

```hlsl
// Generated by KAIN Compiler - Unreal Shader Format
#include "/Engine/Public/Platform.ush"

// Scalar Parameters
float intensity;
float3 color;

// Entry Point
float4 MyFirstShaderPS(float2 uv : TEXCOORD0) : SV_Target0
{
    return float4(color * intensity, 1.0);
}
```

### Phase 4: C++ Header Generation

```
Typed AST → Header Codegen → .h file
```

Generates type-safe C++ bindings:
- `FGlobalShader` derived class
- `SHADER_PARAMETER_STRUCT` compatible layout
- Permutation domain for compile-time branching
- Static `Exec()` helper for RDG integration
- Forward declaration for Dispatch function

**Example Output:**

```cpp
class FMyFirstShaderShader : public FGlobalShader
{
    DECLARE_GLOBAL_SHADER(FMyFirstShaderShader);
    SHADER_USE_PARAMETER_STRUCT(FMyFirstShaderShader, FGlobalShader);

    BEGIN_SHADER_PARAMETER_STRUCT(FParameters, )
        SHADER_PARAMETER(float, intensity)
        SHADER_PARAMETER(FVector3f, color)
    END_SHADER_PARAMETER_STRUCT()

    static void Exec(FRDGBuilder& GraphBuilder, const FParameters& Parameters);
};

void DispatchMyFirstShaderShader(float intensity, FVector3f color);
```

### Phase 5: C++ Implementation Generation

```
Typed AST → Implementation Codegen → .cpp file
```

Generates shader registration and dispatch helpers:
- `IMPLEMENT_GLOBAL_SHADER` with correct plugin path
- Dispatch function that enqueues render commands
- RDG setup and execution
- Proper parameter binding

**Example Output:**

```cpp
#include "MyFirstShader.h"
#include "RenderGraphBuilder.h"

// Register shader with UE5
IMPLEMENT_GLOBAL_SHADER(FMyFirstShaderShader, 
    "/Plugin/MyPlugin/Shaders/MyFirstShader.usf", 
    "MyFirstShaderPS", 
    SF_Pixel);

void DispatchMyFirstShaderShader(float intensity, FVector3f color)
{
    ENQUEUE_RENDER_COMMAND(MyFirstShaderRender)([=](FRHICommandListImmediate& RHICmdList) {
        FRDGBuilder GraphBuilder(RHICmdList);
        
        FMyFirstShaderShader::FParameters* Params = 
            GraphBuilder.AllocParameters<FMyFirstShaderShader::FParameters>();
        Params->intensity = intensity;
        Params->color = color;
        
        FMyFirstShaderShader::Exec(GraphBuilder, *Params);
        GraphBuilder.Execute();
    });
}
```

### Phase 6: File Placement

```
Generated Files → Plugin Structure
```

The build system automatically places files:
- `.usf` → `Plugins/MyPlugin/Shaders/`
- `.h` → `Plugins/MyPlugin/Source/Public/`
- `.cpp` → `Plugins/MyPlugin/Source/Private/`

## Shader Path Resolution

**Critical:** UE5 requires exact shader paths in `IMPLEMENT_GLOBAL_SHADER`.

### Correct Path Format

```cpp
IMPLEMENT_GLOBAL_SHADER(FMyShader, 
    "/Plugin/MyPluginName/Shaders/MyShader.usf",  // Must match plugin_name in KAIN.toml
    "MyShaderPS", 
    SF_Pixel);
```

### How KAIN Handles This

1. Reads `plugin_name` from `KAIN.toml [ue5]` section
2. Generates path: `/Plugin/{plugin_name}/Shaders/{shader_name}.usf`
3. Embeds in all `.cpp` files automatically

**Before KAIN:** Manual find/replace in every file  
**With KAIN:** Automatic, zero errors

## Shader Types

### Pixel Shaders (Fragment)

```kain
shader fragment MyEffect(uv: Vec2) -> Vec4:
    uniform color: Vec3 @0
    return vec4(color, 1.0)
```

Generates:
- Entry point: `MyEffectPS()`
- Shader frequency: `SF_Pixel`
- Exec signature: `Exec(GraphBuilder, Parameters)` (2 args)

### Compute Shaders

```kain
shader compute MyCompute(thread_id: Vec3):
    uniform output: RWTexture2D @0
    output[thread_id.xy] = vec4(1, 0, 0, 1)
```

Generates:
- Entry point: `MyComputeCS()`
- Shader frequency: `SF_Compute`
- `[numthreads(8,8,1)]` attribute
- Exec signature: `Exec(GraphBuilder, Parameters, GroupCount)` (3 args)

## Permutations (Compile-Time Branching)

### Define Permutations

Use `CFG_` or `ENABLE_` prefix for compile-time constants:

```kain
shader fragment Optimized(uv: Vec2) -> Vec4:
    uniform CFG_HIGH_QUALITY: Float @0
    uniform ENABLE_SHADOWS: Float @1
    uniform color: Vec3 @2
    
    var result = color
    
    if CFG_HIGH_QUALITY:
        result = result * 1.5  # Expensive path
    
    if ENABLE_SHADOWS:
        result = result * 0.8  # Shadow calculation
    
    return vec4(result, 1.0)
```

### Generated Permutation Domain

```cpp
class CFG_HIGH_QUALITY : SHADER_PERMUTATION_BOOL("CFG_HIGH_QUALITY");
class ENABLE_SHADOWS : SHADER_PERMUTATION_BOOL("ENABLE_SHADOWS");

using FPermutationDomain = TShaderPermutationDomain<
    CFG_HIGH_QUALITY,
    ENABLE_SHADOWS
>;
```

### Generated USF

```hlsl
#ifdef CFG_HIGH_QUALITY
    result = result * 1.5;
#endif

#ifdef ENABLE_SHADOWS
    result = result * 0.8;
#endif
```

**Result:** Multiple shader variants compiled, zero runtime cost.

## Type Mappings

### KAIN → USF/HLSL

| KAIN Type | USF/HLSL | UE5 C++ |
|-----------|----------|---------|
| `Float` | `float` | `float` |
| `Vec2` | `float2` | `FVector2f` |
| `Vec3` | `float3` | `FVector3f` |
| `Vec4` | `float4` | `FVector4f` |
| `Int` | `int` | `int32` |
| `Bool` | `bool` | `bool` |
| `Texture2D` | `Texture2D` | `FRDGTexture*` |
| `RWTexture2D` | `RWTexture2D<float4>` | `FRDGTextureUAV*` |

### Uniform Bindings

```kain
uniform my_texture: Texture2D @0
uniform my_color: Vec3 @1
uniform my_output: RWTexture2D @2
```

Generates:

```hlsl
Texture2D my_texture : register(t0);
SamplerState my_textureSampler : register(s0);
float3 my_color;  // No register (constant buffer)
RWTexture2D<float4> my_output : register(u2);
```

## MCP Tools Integration

KAIN provides Model Context Protocol (MCP) tools for AI-assisted development.

### Available MCP Tools

Located in `mcp/` directory:

1. **scaffold_plugin** - Generate complete UE5 plugin from KAIN code
2. **compile_kain** - Compile to specific target (ue5, usf, wasm, etc.)
3. **analyze_kain** - Extract features and complexity estimates
4. **validate_kain** - Syntax validation
5. **estimate_complexity** - Development time estimates
6. **compile_multi_target** - Compile to multiple targets simultaneously
7. **fix_header** - Auto-fix UE5 header issues
8. **validate_ue5_plugin** - Comprehensive plugin validation

### MCP Server Setup

The MCP server runs as a Python service:

```bash
cd mcp
python server.py
```

### Tool: scaffold_plugin

**Purpose:** Generate complete UE5 plugin from KAIN source.

**Input:**
```json
{
  "plugin_name": "MyPlugin",
  "kain_code": "shader fragment MyShader...",
  "output_path": "output",
  "plugin_version": "1.0.0",
  "plugin_description": "My plugin"
}
```

**Output:**
- Complete plugin folder structure
- All `.h`, `.cpp`, `.usf` files
- `.uplugin` manifest
- `.Build.cs` file

### Tool: compile_kain

**Purpose:** Compile KAIN to specific target.

**Targets:**
- `ue5` - UE5 C++ (actors, components, structs)
- `usf` - UE5 shaders
- `wasm` - WebAssembly
- `js` - JavaScript
- `rust` - Rust
- `cpp` - C++
- `llvm` - LLVM IR
- `spirv` - SPIR-V
- `hlsl` - DirectX HLSL

**Example:**
```json
{
  "kain_code": "shader fragment...",
  "target": "usf",
  "output_name": "MyShader",
  "output_path": "output"
}
```

### Tool: analyze_kain

**Purpose:** Extract features from KAIN code.

**Returns:**
```json
{
  "datatables": ["ItemData", "WeaponStats"],
  "components": ["HealthComponent", "InventoryComponent"],
  "actors": ["GameMode", "PlayerCharacter"],
  "shaders": ["AtmosphericScattering", "VolumetricFog"],
  "enums": ["ItemRarity", "WeaponType"],
  "complexity": "medium",
  "estimated_lines": 2500

```

### Tool: validate_ue5_plugin

**Purpose:** Validate plugin before UE5 compilation.

**Modes:**
- `quick_check: true` - Syntax validation only (fast)
- `quick_check: false` - Full UHT/UBT validation (slow, requires UE5)

## Workflow Examples

### Example 1: New Plugin from Scratch

```bash
# 1. Create directory
mkdir MyPlugin
cd MyPlugin

# 2. Create KAIN.toml
cat > KAIN.toml << EOF
[package]
name = "MyPlugin"
version = "1.0.0"

[build]
entry = "shaders.kn"

[ue5]
plugin_name = "MyPlugin"
plugin_dir = "."
shaders = []  # Auto-detect
EOF

# 3. Write shaders
cat > shaders.kn << EOF
shader fragment Tint(uv: Vec2) -> Vec4:
    uniform color: Vec3 @0
    return vec4(color, 1.0)
EOF

# 4. Build
kain build --ue5

# 5. Copy to UE5 project
cp -r MyPlugin/MyPlugin /path/to/UE5Project/Plugins/
```

### Example 2: Iterative Development

```bash
# Terminal 1: Watch mode
kain shaders.kn -t usf -o Output --plugin MyPlugin -w

# Terminal 2: Edit shaders
vim shaders.kn  # Auto-recompiles on save

# Terminal 3: Copy to UE5
while true; do
  cp Output/*.usf /path/to/UE5/Plugins/MyPlugin/Shaders/
  cp Output/*.h /path/to/UE5/Plugins/MyPlugin/Source/Public/
  cp Output/*.cpp /path/to/UE5/Plugins/MyPlugin/Source/Private/
  sleep 2
done
```

### Example 3: Multi-Plugin Project

```
MyProject/
├── PluginA/
│   ├── KAIN.toml
│   └── shaders.kn
├── PluginB/
│   ├── KAIN.toml

```

## Troubleshooting

### Issue: "No [ue5] section in KAIN.toml"

**Solution:** Add `[ue5]` section with `plugin_name`:

```toml
[ue5]
plugin_name = "MyPlugin"
plugin_dir = "."
```

### Issue: "Entry file not found"

**Solution:** Ensure `[build] entry` points to existing `.kn` file:

```toml
[build]
entry = "shaders.kn"  # Must exist in same directory as KAIN.toml
```

### Issue: Shader path mismatch in UE5

**Symptom:** Plugin crashes with "Failed to find shader"

**Solution:** Verify `plugin_name` in KAIN.toml matches actual plugin folder name:

```toml
[ue5]
plugin_name = "MyPlugin"  # Must match Plugins/MyPlugin/
```

### Issue: Parameter count mismatch

**Symptom:** `DispatchMyShader: function does not take N arguments`

**Solution:** Rebuild with latest compiler (fixed in recent versions):

```bash
cargo build --release
kain build --ue5
```

### Issue: Missing includes in generated headers

**Solution:** Use MCP `fix_header` tool:

```json
{
  "file_path": "Source/Public/MyShader.h",
  "plugin_name": "MyPlugin",
  "output_name": "MyShader",
  "required_modules": ["Core", "RenderCore", "RHI"]
}
```

## Performance Tips

## Best Practices

1. **One source file per plugin** - Easier to manage
2. **Descriptive shader names** - `AtmosphericScattering` not `Shader1`
3. **Version control `.kn` files** - Not generated C++
4. **Use KAIN.toml** - Don't rely on CLI flags
5. **Test in UE5 immediately** - Catch issues early
6. **Document uniforms** - Future you will thank you
