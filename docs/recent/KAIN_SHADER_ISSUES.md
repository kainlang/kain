# KAIN Compiler Issue Report: Shader Parameter Generation

## Executive Summary
The primary blocker for the FluidFlow plugin build is a fundamental mismatch between **Unreal Engine's Shader Parameter system** and the **C++ code generated by KAIN**.

The compiler is attempting to pass `UActorComponent` pointers directly to GPU shaders via `SHADER_PARAMETER` macros. This is invalid because:
1.  **GPU Memory Layout:** GPUs require Plain Old Data (POD) structs (floats, vectors, ints) with specific alignment. `UObjects` are complex CPU objects with vtables and GC data.
2.  **Missing Includes:** The generated headers reference these component types without including their corresponding header files.

---

## 1. The "UObject in Shader" Error (Critical)

### The Problem
In every generated shader header (e.g., `LatticeBoltzmannCollision.h`), the code uses Component classes in `SHADER_PARAMETER` macros.

**Broken Code (Current):**
```cpp
// internal vtable + GC data makes this invalid for GPU
SHADER_PARAMETER(PhysicalPropertiesComponent, physics) 
```

**Compiler Error:**
```
error C2923: 'TShaderParameterTypeInfo': 'PhysicalPropertiesComponent' is not a valid template type argument
error C2057: expected constant expression
```

### The Fix
You must define a simple C++ struct (POD) that mirrors the data you want to send to the GPU, and use *that* in the macro.

**Fixed Code (Target):**
```cpp
// 1. Define a POD struct for the data
struct FPhysicalPropertiesData
{
    float viscosity;
    float density;
    float gravity_scale;
    // ... all other float/int properties from the component
};

// 2. Use the POD struct in the macro
SHADER_PARAMETER(FPhysicalPropertiesData, physics)
```

---

## 2. Missing Header Includes

### The Problem
The generated shader files (`.h`) reference types like `PhysicalPropertiesComponent` but never include their definition.

**Broken Code:**
```cpp
#include "CoreMinimal.h"
#include "GlobalShader.h"
// ... missing component includes ...

class FLatticeBoltzmannCollisionShader ...
```

**Compiler Error:**
```
error C2065: 'PhysicalPropertiesComponent': undeclared identifier
```

### The Fix
Add the necessary includes to the top of the shader header files.

**Fixed Code:**
```cpp
#include "CoreMinimal.h"
#include "FPhysicalPropertiesComponent.h" // <--- Added
#include "FTurbulenceComponent.h"         // <--- Added
```

---

## 3. Dispatch Logic mismatch in `AHyperFluidController.cpp`

### The Problem
Since the shader parameters change from "Component Pointer" to "Data Struct", the code that calls the shader must be updated to populate this struct.

**Broken Code (Current):**
```cpp
// Passing the component itself
AddPass_LatticeBoltzmannCollision(
    GraphBuilder, 
    World->simulation->physics, // <--- UPhysicalPropertiesComponent*
    ...
);
```

### The Fix
You need to construct the data struct from the component's values before dispatching.

**Fixed Code:**
```cpp
// 1. Create the data struct
FLatticeBoltzmannCollisionShader::FPhysicalPropertiesData PhysicsData;
PhysicsData.viscosity = World->simulation->physics->viscosity;
PhysicsData.density = World->simulation->physics->density;
// ... copy other fields ...

// 2. Pass the data struct
AddPass_LatticeBoltzmannCollision(
    GraphBuilder, 
    PhysicsData, // <--- Passed by value
    ...
);
```

## Summary of Files to Fix

1.  **For EACH Shader (77 total):**
    *   **File:** `Source/FluidFlow/Public/[ShaderName].h`
    *   **Action:** 
        1.  Add missing `#include` for components.
        2.  Define a POD struct (e.g., `F[ComponentName]Data`) for each component parameter.
        3.  Update `SHADER_PARAMETER` macros to use the POD struct.
        4.  Update the `AddPass_...` function signature to take the POD struct by value.

2.  **For the Controller:**
    *   **File:** `Source/FluidFlow/Private/AHyperFluidController.cpp`
    *   **Action:** Update every `AddPass_...` call to create the POD struct from the component and pass it.
