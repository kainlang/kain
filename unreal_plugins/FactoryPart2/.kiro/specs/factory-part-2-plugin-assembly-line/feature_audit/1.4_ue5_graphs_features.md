# 1.4 UE5 Graphs Features

> **Crate:** `ue5-graphs`  
> **Status:** Production — both graph runtime and graph editor implemented  
> **Last Updated:** 2026-03-01

---

## Overview

The `ue5-graphs` crate generates two categories of graph-related UE5 C++ code:

1. **Graph Runtime** — `UEdGraph`-compatible runtime graphs with node data, instance execution, and asset management (for in-game use)
2. **Graph Editor** — `UEdGraphNode` subclasses for custom KAIN graph editors with pin types, schema, and factory registration

**Size:** 35KB NodeData codegen + 27KB factory generator + 23KB instance codegen

---

## 1. Graph Runtime System

**Status:** ✅ Fully Implemented

### Description
`@graph_runtime` constructs compile to runtime graph execution systems with node data classes, graph instances, and asset containers.

### KAIN Syntax
```kain
@graph_runtime
graph DialogueSystem:
    @node_data
    node SpeakerNode:
        speaker_name: String = "NPC"
        dialogue_text: String = "Hello!"
        
        @input_pin
        in_exec: Exec
        
        @output_pin
        next: Exec
    
    @node_data
    node ChoiceNode:
        choices: Array<String> = []
        
        @input_pin
        in_exec: Exec
        
        @output_pin
        choice_0: Exec
        
        @output_pin
        choice_1: Exec
    
    @node_data
    node ConditionNode:
        condition_var: String = "has_key"
        
        @input_pin
        in_exec: Exec
        
        @output_pin
        true_branch: Exec
        
        @output_pin
        false_branch: Exec
```

UCLASS()

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category="Dialogue")
    FString SpeakerName = TEXT("NPC");
    
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category="Dialogue")

void UNodeData_SpeakerNode::ExecuteNode(UGraphInstance* Instance) {
    // Display dialogue
    UE_LOG(LogTemp, Log, TEXT("%s: %s"), *SpeakerName, *DialogueText);
    
    // Trigger next node via "next" output pin
    Instance->ExecuteConnectedNode(this, TEXT("next"));
}

    return {
        FNodePinDesc{TEXT("in_exec"), EPinType::Exec, EPinDirection::Input}

}

TArray<FNodePinDesc> UNodeData_SpeakerNode::GetOutputPins() const {
    return {
        FNodePinDesc{TEXT("next"), EPinType::Exec, EPinDirection::Output}
    };
}

    // Evaluate condition
    bool bConditionMet = Instance->GetLocalVar(*ConditionVar).AsBool();

    Instance->ExecuteConnectedNode(this, PinName);

### Generated UE5 C++ — Graph Instance

```cpp
UCLASS()
class UDialogueSystemInstance : public UGraphInstanceBase {
    GENERATED_BODY()
public:
    // Execute graph from a specific node
    UFUNCTION(BlueprintCallable, Category="Dialogue")
    void ExecuteFrom(UNodeDataBase* StartNode);
    
    // Execute connected node via output pin
    void ExecuteConnectedNode(UNodeDataBase* CurrentNode, FName OutputPinName);
    
    // Evaluate pin condition
    bool EvaluatePin(FName PinName);
    
    // Local variable storage
    UFUNCTION(BlueprintCallable, Category="Dialogue")
    void SetLocalVar(FName Name, FInstanceValue Value);
    
    UFUNCTION(BlueprintCallable, Category="Dialogue")
    FInstanceValue GetLocalVar(FName Name);
    
private:
    TMap<FName, FInstanceValue> LocalVariables;
    TMap<UNodeDataBase*, TMap<FName, UNodeDataBase*>> Connections;
};

void UDialogueSystemInstance::ExecuteFrom(UNodeDataBase* StartNode) {
    if (!StartNode) return;
    
    // Execute node
    StartNode->ExecuteNode(this);
}

void UDialogueSystemInstance::ExecuteConnectedNode(UNodeDataBase* CurrentNode, FName OutputPinName) {
    if (!Connections.Contains(CurrentNode)) return;
    
    TMap<FName, UNodeDataBase*>& NodeConnections = Connections[CurrentNode];
    if (!NodeConnections.Contains(OutputPinName)) return;
    
    UNodeDataBase* NextNode = NodeConnections[OutputPinName];
    ExecuteFrom(NextNode);
}
```

## 2. Graph Editor System

**Status:** ✅ Fully Implemented

### Description
`@graph_editor` constructs compile to `UEdGraphNode` subclasses for custom graph editors in the UE5 editor.

### KAIN Syntax
```kain
@graph_editor
graph DialogueGraph:
    @node_type
    node NPCNode:
        properties:
            SpeakerName: String = "NPC"
            DialogueText: String = "Hello!"
        inputs:
            InExec: Exec
        outputs:
            Next: Exec
    
    @node_type
    node PlayerChoiceNode:
        properties:
            Choices: Array<String> = []
        inputs:
            InExec: Exec
        outputs:
            Choice0: Exec
            Choice1: Exec
    
    @node_type
    node BranchNode:
        properties:
            ConditionVar: String = "has_key"
        inputs:
            InExec: Exec
        outputs:
            True: Exec
            False: Exec
```

const FPinConnectionResponse UDialogueGraphSchema::CanCreateConnection(const UEdGraphPin* A, const UEdGraphPin* B) const {
    // Validate pin types match
    if (A->PinType.PinCategory != B->PinType.PinCategory) {
        return FPinConnectionResponse(CONNECT_RESPONSE_DISALLOW, TEXT("Pin types do not match"));
    }
    
    // Validate direction (input to output or output to input)
    if (A->Direction == B->Direction) {
        return FPinConnectionResponse(CONNECT_RESPONSE_DISALLOW, TEXT("Cannot connect pins of the same direction"));
    }
    
    return FPinConnectionResponse(CONNECT_RESPONSE_MAKE, TEXT(""));
}

## 3. Pin Type System

**Status:** ✅ Fully Implemented

### Description
Comprehensive pin type system supporting all UE5 data types.

### Supported Pin Types

| Pin Type | UE5 Type | Description |
|----------|----------|-------------|
| `Exec` | Execution flow pin | White execution wire |
| `Bool` | `bool` | Boolean data pin |
| `Int` | `int32` | Integer data pin |
| `Float` | `float` | Float data pin |
| `String` | `FString` | String data pin |
| `Object` | `UObject*` | Object reference pin |
| `Struct` | Struct data pin | Custom struct data |
| `Enum` | Enum data pin | Enum value |
| `Wildcard` | `FWildcardProperty` | Accepts any type |
| `Array` | `TArray<T>` | Array data pin |

### Pin Direction
- `Input` — data flows into node
- `Output` — data flows out of node

### Pin Attributes

| Attribute | Effect |
|-----------|--------|
| `@input_pin` | Marks field as input pin |
| `@output_pin` | Marks field as output pin |

### Factory Examples
- **All graph plugins** — pin types used throughout graph systems

### Implementation Details
- **Pin Types:** `node_types.rs` (3KB)
- **Pin Creation:** `CreatePin()` in `AllocateDefaultPins()`
