# 1.1 KAIN Core Language Features

> **Crate:** `kain-core`  
> **Status:** Production — the heart of the compiler  
> **Last Updated:** 2026-03-01

---

## Overview

`kain-core` provides the foundational language features that all KAIN programs use. This includes the lexer, parser, AST, type checker, effect system, compile-time execution, pattern matching, actor concurrency, Python FFI, and the standard library loader.

---

## 1. Actor Concurrency (Erlang-Style)

**Status:** ✅ Fully Implemented

### Description
First-class actor system with channel-based message passing. Actors are isolated units of state with message handlers. No shared mutable state — all communication via messages.

### KAIN Syntax
```kain
actor ChatRoom:
    var messages: Array<String> = []
    var users: Array<String> = []
    
    on Join(name: String):
        push(users, name)
        broadcast("{name} joined")
    
    on Message(from: String, text: String):
        push(messages, "{from}: {text}")
        broadcast("{from}: {text}")
```

### Implementation Details
- **AST Node:** `Item::Actor` with `handlers: Vec<Handler>`
- **Runtime:** `runtime.rs` (138KB) — tree-walking interpreter with actor mailbox
- **Message Dispatch:** `flume` channels for async message passing
- **Spawn:** `Expr::Spawn` creates new actor instances
- **Send:** `Expr::SendMsg` sends messages to actor mailboxes

### Factory Examples
- **NarrativeGraph** — dialogue system actors managing conversation state
- **TitanGraph** — quest system actors coordinating quest progression
- **TacticalRaidGAS** — game mode actors managing team state

### Compilation Targets
- **Interpret/Test:** Full actor runtime with mailbox and message dispatch
- **UE5:** Actors compile to `AActor` subclasses with RPC handlers (see `ue5` crate)
- **WASM/JS:** Actor runtime via message queue simulation
- **LLVM:** Native actor runtime with thread pool

## 2. Effect Tracking System

**Status:** ✅ Fully Implemented

### Description
Side effects are part of the type system. Functions declare their effects via `with` clauses. The effect checker enforces the effect lattice — `Pure` functions cannot call `IO` functions.

### Effect Types (8 Total)

| Effect | Meaning | Can Call |
|--------|---------|----------|
| `Pure` | No side effects | Only `Pure` |
| `IO` | File/Network/Console | `Pure`, `IO` |
| `Async` | Can `await` | `Pure`, `Async` |
| `GPU` | Runs on graphics hardware | `Pure`, `GPU` |
| `Reactive` | Triggers UI updates | `Pure`, `Reactive` |
| `Unsafe` | Breaks safety guarantees | **Anything** (top element) |
| `Alloc` | Memory allocation | `Pure`, `Alloc` |
| `Panic` | Can abort | `Pure`, `Panic` |

### KAIN Syntax
```kain
fn factorial(n: Int) -> Int with Pure:
    match n:
        0 => 1
        _ => n * factorial(n - 1)

fn read_config() -> String with IO:
    read_file("config.txt")

fn process_async(data: Array<Int>) -> Int with Async:
    let result = await fetch_data()
    return result
```

### Implementation Details
- **AST Node:** `Function::effects: Option<EffectSet>`
- **Type Checker:** `types.rs` (24KB) — `check_function_effects()` validates call graph
- **Effect Lattice:** `effects.rs` (5KB) — `EffectSet::can_call()` enforces hierarchy
- **Inference:** Effects can be inferred from function body if not explicitly declared

### Factory Examples
- **VoxelForgePro** — `Pure` noise functions for deterministic terrain generation
- **FluidFlow** — `GPU` effect for compute shader functions
- **NarrativeGraph** — `IO` effect for dialogue file loading

### Compilation Targets
- **All targets:** Effect checking happens at compile time, no runtime overhead
- **UE5:** `Pure` functions marked `const` in C++
- **GPU targets:** Only `Pure` and `GPU` effects allowed in shaders

## 3. Compile-Time Execution (Comptime)

**Status:** ✅ Fully Implemented

### Description
Zig-style compile-time execution. Code in `comptime` blocks runs during compilation. No separate macro language needed.

### KAIN Syntax
```kain
comptime:
    let build_version = "1.0.0"
    let max_players = 64

fn get_version() -> String:
    return build_version  # Compile-time constant

const PLAYER_LIMIT: Int = max_players
```

### Implementation Details
- **AST Node:** `Item::Comptime { block: Block }`
- **Evaluator:** `comptime.rs` (5KB) — `eval_program()` runs comptime blocks before type checking
- **Expansion:** Comptime values are inlined into the AST before codegen
- **Limitations:** Comptime code cannot perform I/O or call non-Pure functions

### Factory Examples
- **VoxelForgePro** — comptime grid size calculations for shader dispatch
- **Cinema4DMograph** — comptime array size constants for modifier stacks
- **MetaFitter** — comptime bone name string constants

### Compilation Targets
- **All targets:** Comptime evaluation happens once during compilation
- **Output:** Comptime values become constants in generated code

## 4. Pattern Matching

**Status:** ✅ Fully Implemented

### Description
Exhaustive pattern matching with destructuring, range patterns, and wildcard patterns. Compiler enforces exhaustiveness.

### KAIN Syntax
```kain
fn describe(x: Int) -> String:
    match x:
        0 => "zero"
        1..10 => "small"
        11..100 => "medium"
        _ => "large"

fn process_result(r: Result<Int, String>) -> Int:
    match r:
        Ok(value) => value
        Err(msg) => 
            println("Error: {msg}")
            return -1

enum ItemRarity:
    Common
    Rare
    Epic
    Legendary

fn get_color(rarity: ItemRarity) -> String:
    match rarity:
        Common => "gray"
        Rare => "blue"
        Epic => "purple"
        Legendary => "orange"
```

### Pattern Types
- **Literal patterns:** `0`, `"hello"`, `true`
- **Range patterns:** `1..10`, `0..=100`
- **Wildcard:** `_` matches anything
- **Enum variants:** `Ok(value)`, `Err(msg)`
- **Tuple destructuring:** `(x, y, z)`
- **Struct destructuring:** `Point { x, y }`

### Implementation Details
- **AST Node:** `Expr::Match { scrutinee, arms }`
- **Parser:** `parser.rs` (272KB) — recursive descent with pattern parsing
- **Type Checker:** Validates exhaustiveness and type compatibility
- **Codegen:** Compiles to switch statements or if-else chains depending on target

### Factory Examples
- **NarrativeGraph** — pattern matching on dialogue node types
- **TitanGraph** — pattern matching on quest states
- **TacticalRaidGAS** — pattern matching on ability activation results

### Compilation Targets
- **UE5:** Switch statements for enums, if-else for ranges
- **WASM/JS:** If-else chains
- **LLVM:** Native switch instructions

## 5. Python FFI (pyo3 Integration)

**Status:** ✅ Fully Implemented

### Description
Direct Python interop via pyo3. Call Python functions from KAIN code. Useful for prototyping, data processing, and leveraging Python libraries.

### KAIN Syntax
```kain
fn calculate_sqrt(x: Float) -> Float:
    let result = py_call("math.sqrt", [x])
    return result

fn load_json_data(path: String) -> String:
    return py_call("json.load", [path])
```

### Implementation Details
- **Runtime:** `runtime.rs` (138KB) — `py_call()` function
- **Backend:** `pyo3` crate for Python C API bindings
- **Type Conversion:** Automatic conversion between KAIN and Python types
- **Limitations:** Only available in interpreter mode (`kain run`, `kain test`)

### Supported Python Types
- **Primitives:** int, float, str, bool
- **Collections:** list, dict, tuple
- **None:** Maps to KAIN `None`

### Factory Examples
- **VoxelForgePro** — Python noise library for terrain prototyping
- **MetaFitter** — Python data processing for MetaHuman bone mapping
- **Cinema4DMograph** — Python math libraries for mograph calculations

### Compilation Targets
- **Interpret/Test:** Full Python FFI via pyo3
- **Other targets:** Python FFI not available (compile-time error if used)

## 6. Type System (Ownership, Borrowing, No Null)

**Status:** ✅ Fully Implemented

### Description
Rust-inspired type system with ownership, borrowing, and no null pointers. Memory-safe by default without garbage collection.

### Core Type Features

#### Ownership
- Every value has a single owner
- When owner goes out of scope, value is dropped
- Move semantics by default

#### Borrowing
- Immutable references: `&T`
- Mutable references: `&mut T`
- Borrow checker enforces aliasing rules

#### No Null
- `Option<T>` instead of null pointers
- Compiler enforces exhaustive handling

### KAIN Type System

| KAIN Type | Description |
|-----------|-------------|
| `Unit` | Empty type `()` |
| `Bool` | Boolean |
| `Int` | Signed integer (i32 default) |
| `Float` | Floating point (f32 default) |
| `String` | UTF-8 string |
| `Char` | Single character |
| `Array<T, N>` | Fixed-size array |
| `Slice<T>` | Dynamic array view |
| `Option<T>` | Optional value |
| `Result<T, E>` | Result with error |
| `Tuple<T1, T2, ...>` | Tuple |
| `Ref<T>` | Immutable reference |
| `RefMut<T>` | Mutable reference |
| `Ptr<T>` | Raw pointer (unsafe) |
| `PtrMut<T>` | Mutable raw pointer (unsafe) |

### Implementation Details
- **AST Node:** `Type` enum in `ast.rs` (67KB)
- **Type Checker:** `types.rs` (24KB) — `check()` validates types and ownership
- **Resolved Types:** `ResolvedType` with concrete sizes (`IntSize`, `FloatSize`)
- **Generics:** Monomorphization via `monomorphize.rs` (66KB)

### Factory Examples
- **All plugins** — type system is foundational to all KAIN code
- **VoxelForgePro** — `Option<VoxelData>` for sparse voxel grids
- **NarrativeGraph** — `Result<DialogueNode, String>` for dialogue loading

### Compilation Targets
- **UE5:** Maps to UE5 types (`TArray`, `TOptional`, pointers for UObject)
- **WASM:** Reference counting for heap types
- **LLVM:** Native RAII with scope-based cleanup
- **Rust:** Direct mapping to Rust types

## 7. Macro System (Hygienic Macros, Code as Data)

**Status:** ✅ Fully Implemented

### Description
Lisp-inspired macro system with hygienic expansion. Macros are code transformations that run at compile time.

### KAIN Syntax
```kain
macro repeat!(count, body):
    # Expands to a loop that runs body count times
    for i in 0..count:
        body

# Usage
repeat!(5, println("Hello"))
```

### Implementation Details
- **AST Node:** `Item::Macro { name, params, body }`
- **Expansion:** Macros expand during parsing before type checking
- **Hygiene:** Variable capture is prevented via scope tracking
- **Limitations:** Macro system is basic — no pattern matching in macro args yet

### Factory Examples
- **Cinema4DMograph** — macros for repetitive modifier setup
- **VoxelForgePro** — macros for shader permutation generation
- **TacticalRaidGAS** — macros for ability attribute boilerplate

### Compilation Targets
- **All targets:** Macros expand at compile time, no runtime representation

## 8. Low-Level Memory Pipeline

**Status:** ✅ Fully Implemented (Feb 2026)

### Description
Low-level memory operations for C interop, FFI, and systems programming. Provides explicit control over memory layout, alignment, and pointer arithmetic.

### Low-Level Expressions

| Expression | Meaning |
|------------|---------|
| `addr_of(x)` | Take address of value |
| `ptr_offset(p, i)` | Pointer arithmetic |
| `mem_load(p)` | Dereference pointer |
| `mem_store(p, v)` | Store through pointer |
| `sizeof_type("T")` | Size of type |
| `alignof_type("T")` | Alignment of type |
| `alloca(T)` | Stack allocation |
| `uninit(T)` | Uninitialized storage |
| `alloc(size, T)` | Heap allocation |
| `realloc(p, size, T)` | Heap reallocation |

### Implementation Details
- **AST Nodes:** `Expr::AddrOf`, `Expr::PtrOffset`, `Expr::MemLoad`, `Expr::MemStore`, etc.
- **Lowering:** `low_level_memory.rs` (88KB) — `lower_typed_program_memory_for_target()`
- **Layout Registry:** `StructLayoutInfo` tracks size, alignment, field offsets
- **ABI Layer:** `low_level_abi.rs` (9KB) — C ABI policies (LP64, LLP64)
- **Backend Capabilities:** Per-target support for raw pointers, alloca, helper emission

### Factory Examples
- **LowLevelAbiSmoke** — C struct interop testing
- **LowLevelRuntimeSmoke** — pointer arithmetic and memory operations
- **MetaHumanVAT** — direct memory access for vertex animation textures

### Compilation Targets
- **LLVM/Cpp/Rust:** Native pointer operations
- **WASM/JS/TS:** Runtime helper functions (`__kain_addr_of`, `__kain_ptr_offset`, etc.)
- **UE5:** Pointer operations for UObject manipulation

## 9. Standard Library Loader

**Status:** ✅ Fully Implemented (Feb 2026)

### Description
Data-driven standard library system with per-target profiles. Automatically loads and prepends stdlib functions to every compilation.

### Target Profiles

| Target | Profile Path | Functions |
|--------|--------------|-----------|
| `Ue5` | `stdlib/ue5/` | 200+ UE5-specific functions |
| `Wasm` | `stdlib/` | Core functions |
| `Ks` | `stdlib/` | JavaScript-compatible functions |
| `Llvm` | `stdlib/` | Native functions |

### Discovery Order
1. `$KAIN_STDLIB_PATH` environment variable
2. Sibling `stdlib/` of compiler binary
3. Workspace `stdlib/`

### Implementation Details
- **Loader:** `stdlib.rs` (26KB) — `load_stdlib_for_target()`
- **Profile System:** `TARGET_PROFILE_ORDER` maps targets to profile directories
- **Alphabetical Loading:** Files loaded in alphabetical order for deterministic builds
- **Prepending:** Stdlib source prepended to user source before parsing

### Factory Examples
- **All plugins** — stdlib is automatically loaded for every compilation
- **VoxelForgePro** — uses 100+ shader stdlib functions
- **NarrativeGraph** — uses actor/gameplay stdlib functions

### Compilation Targets
- **All targets:** Stdlib loaded automatically based on target

## 10. Diagnostics System

**Status:** ✅ Fully Implemented (Feb 2026)

### Description
Rich error reporting with source context, file:line:col locations, and color-coded output. Uses `ariadne` for error rendering.

### Features
- **SpanMapper:** Maps byte-offset `Span` to `(line, col)` with precomputed line-start table
- **Diagnostics:** Renders errors with source context and caret
- **Error Enhancement:** `enhance_error_with_location()` upgrades codegen errors with human-readable locations
- **Diagnostic Codes:** Typed error codes for all error categories

### Implementation Details
- **SpanMapper:** `diagnostics.rs` (14KB) — `SpanMapper::new()` precomputes line starts
- **Error Rendering:** `ariadne` crate for color-coded output
- **Error Types:** `KainError` enum in `error.rs` (25KB)

### Factory Examples
- **All plugins** — diagnostics used for all compilation errors
- **VoxelForgePro** — shader validation errors with file:line:col
- **NarrativeGraph** — graph validation errors with source context

## 11. Monomorphizer (Generic Instantiation)

**Status:** ✅ Fully Implemented

### Description
Generic function and struct instantiation via monomorphization. Type arguments are inferred from call sites.

### Features
- **Generic Functions:** `fn foo<T>(x: T) -> T`
- **Generic Structs:** `struct Box<T> { value: T }`
- **Type Inference:** Missing type arguments inferred from usage
- **Async Lowering:** Async functions lowered to state machines

### Implementation Details
- **Monomorphizer:** `monomorphize.rs` (66KB)
- **Type Unification:** `unify(param_type, arg_type, bindings)`
- **Instantiation:** `MonoContext::instantiate()` creates concrete instances
- **Name Mangling:** `mangle_types()` creates disambiguating suffixes

### Factory Examples

## 12. Language Capabilities Registry

**Status:** ✅ Fully Implemented

### Description
Data-driven feature flags controlling parser and runtime behavior. Allows enabling/disabling language features per compilation.

### Capabilities

| Capability | Default | Description |
|------------|---------|-------------|
| `ParserStructLiterals` | Disabled | `Type { field: val }` syntax |
| `ParserBitwiseAnd` | Enabled | `&` operator |
| `ParserBitwiseOr` | Enabled | `\|` operator |
| `ParserBitwiseXor` | Enabled | `^` operator |
| `ParserShiftLeft` | Enabled | `<<` operator |
| `ParserShiftRight` | Enabled | `>>` operator |
| `RuntimeBitwiseAnd` | Enabled | Bitwise AND runtime |
| `RuntimeBitwiseOr` | Enabled | Bitwise OR runtime |
| `RuntimeBitwiseXor` | Enabled | Bitwise XOR runtime |
| `RuntimeShl` | Enabled | Shift left runtime |
| `RuntimeShr` | Enabled | Shift right runtime |

### Implementation Details
- **Registry:** `language_features.rs` (7KB)
- **Global Default:** `DEFAULT_LANGUAGE_CAPABILITIES` lazy static
- **Override:** `LanguageCapabilities::with_override()`
