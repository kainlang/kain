# Task 5.1 Summary: Replace `default_actor_run` Bootstrap Path

## Overview

Replaced the fallback `default_actor_run` wrapper with proper actor-specific entrypoints in LLVM codegen, implementing Requirement 5.1 from the KAIN Native Runtime Completion spec.

## Changes Made

### 1. LLVM Codegen Actor Spawn Fix

**File:** `crates/kain-sys-codegen/src/codegen_llvm/mod.rs`

**Before:**
```rust
// Spawn
// Cast func to i8*
let func_ptr = "bitcast (void (i8*)* @default_actor_run to i8*)";
```

**After:**
```rust
// Spawn using proper actor bootstrap ABI
// Use the actor-specific run function instead of default_actor_run
let actor_run_fn = format!("{}_run", actor);
let func_ptr = format!("bitcast (void (i8*)* @{} to i8*)", actor_run_fn);
```

**Impact:** Actor spawning now uses the actor-specific `{ActorName}_run` function that is already generated by the `compile_actor` method, instead of routing through a generic fallback wrapper.

### 2. Test Update

**File:** `crates/kain-sys-codegen/tests/llvm_codegen_test.rs`

Updated the `llvm_generates_actor_spawn_and_send_message_paths` test to verify that:
- Actor-specific entrypoints are used: `@Printer_run`
- The old `default_actor_run` fallback is NOT used

### 3. Runtime Documentation

**File:** `runtime/native/src/core/kain_runtime_core.c`

Added deprecation comment to `default_actor_run` function explaining:
- It was used as a fallback wrapper for actor spawning
- LLVM codegen now emits actor-specific entrypoints
- Function remains for backward compatibility only

## Technical Details

### Actor Entrypoint Generation

The LLVM backend already generates actor-specific run functions with the signature:
```llvm
define void @{ActorName}_run(i8* %arg)
```

These functions:
1. Cast the `i8* %arg` to the actor struct pointer
2. Extract the mailbox from field 0
3. Enter a message processing loop
4. Switch on message tags to dispatch to handlers
5. Process handler bodies with access to actor state

### Spawn Call Path

The spawn now correctly passes the actor's entrypoint:
```llvm
call void @KAIN_spawn(i8* bitcast (void (i8*)* @Printer_run to i8*), i8* %actor_mem)
```

This ensures that when `KAIN_spawn` creates a thread, it calls the correct actor's message loop.

## Requirements Satisfied

✅ **Requirement 5.1:** "When LLVM emits actor-backed programs, the System SHALL bootstrap actors through the emitted actor entrypoint rather than the current default wrapper path"

## Next Steps

This change establishes the correct actor bootstrap path in LLVM codegen. Future work (Tasks 5.2-5.6) will:

1. Define proper actor runtime structs and headers (Task 5.2)
2. Implement mailbox-backed actor spawn and shutdown (Task 5.3)
3. Add actor lifecycle and supervision semantics (Task 5.4)
4. Implement actor registry and monitoring (Task 5.5)
5. Add actor runtime conformance tests (Task 5.6)

The current implementation still uses the old `KAIN_spawn(void*, void*)` signature. The full actor bootstrap ABI defined in `runtime/native/include/kain_runtime_actor.h` uses:
```c
typedef KainActorExitReason (*KainActorBootstrapFn)(
    KainActorId actor_id,
    KainActorMailbox* mailbox,
    void* user_data
);
```

Future tasks will migrate to this richer ABI that provides actor ID, typed mailbox, and proper exit reason handling.
