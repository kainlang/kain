# HEARTBEAT

## Kain pipeline heartbeat

- Cadence: once per hour unless the user changes it.
- Goal: keep the Kain pipeline moving toward native, GPU-aware app authoring parity, with 3D power features taking priority over polish-only smoke work.
- Operating rule: use the Codex CLI for implementation work and treat it as the default coding-agent path.
- If a Codex usage-limit error appears, check usage and seat availability before assuming the run is blocked.
- Keep updates short, frequent, and concrete.
- Track the live target tree under `F:/kain`.
- Maintain the broader goal of eventually authoring large native applications in Kain, including UE5 / ZBrush / Substance-style workflows where the language surface supports it.
- For 3D passes, bias toward power features first, especially SPIR-V-backed compute, renderer architecture, scene/runtime systems, and other high-leverage core capabilities.
- Avoid spending a pass on smoke or reporting work unless it directly unlocks core 3D capability.
