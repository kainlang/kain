# UI Bundle Startup Smoke Fixture

**Purpose:** Validates compiled UI bundle loading and component metadata

**Requirements:** 4.2, 8.1, 13.4, 13.5

---

## What This Tests

This fixture validates the UI bundle startup path:

1. **UI component compilation** - Can the compiler emit UI components?
2. **Compiled UI bundle structure** - Is the bundle structure valid?
3. **Component metadata validation** - Can the runtime validate component metadata?
4. **UI runtime initialization** - Can the UI runtime initialize successfully?
5. **Startup diagnostics** - Does the runtime emit diagnostics on success?

---

## Artifacts

- `main.kn` - Minimal UI component program
- `kain_runtime_contract.json` - Contract with UI requirements
- `README.md` - This file

**Note:** The compiled UI bundle is generated by the compiler/driver and not checked into version control.

---

## Usage

### Compile

```bash
cd runtime/fixtures/ui_startup
kain build main.kn --target rust
```

### Expected Behavior

- Compilation succeeds
- Runtime contract is loaded successfully
- Compiled UI bundle is generated and loaded
- Component metadata is validated
- No startup errors or warnings

### Failure Modes

If this fixture fails, it indicates:

- UI component compilation is broken
- Compiled UI bundle structure is invalid
- Component metadata validation is broken
- UI runtime initialization is broken
- Service bindings for UI are broken

## Notes

- This is the simplest possible UI component
- No interactivity, no complex layout, no state
- Focus is purely on bundle loading and metadata validation
- Should work on all platforms (Rust-native UI host)
- This fixture tests `runtime/native/src/ui/kain_ui_compiled_bundle.c` (when targeting raw-native)
- For Rust-native target, tests `kain-ui` and `kain-ui-native` crates
